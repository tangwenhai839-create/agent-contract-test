# Governance

Agent Contract Test begins as a maintainer-led project and is intended to grow into a multi-maintainer community.

## Roles

- **Contributors** submit issues, fixtures, documentation, and code.
- **Reviewers** demonstrate sustained, accurate review and may approve changes in owned areas.
- **Maintainers** merge changes, manage releases, triage security reports, and evolve governance.

## Decisions

Routine decisions are made through reviewed pull requests. Changes to the stable schema, security boundaries, telemetry policy, license, or governance require a public design issue and documented maintainer agreement.

## Maintainer expectations

Maintainers should:

- triage actionable reports;
- review contributions respectfully and transparently;
- avoid overstating adoption or security guarantees;
- publish release notes and compatibility changes; and
- disclose conflicts of interest relevant to project decisions.

## Becoming a maintainer

Maintainer invitations are based on sustained contribution quality, review judgment, security awareness, and community conduct—not commit count alone. As the community grows, ownership will be delegated by adapters, assertions, documentation, and release engineering.
